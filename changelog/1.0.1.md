# Perfomant Boom 1.0.1

## Explosion correctness

- Keep live-world reads on the server thread and spread ray calculation and mutation across ticks instead of reading mutable chunk palettes from a worker thread.
- Align ray directions, float stepping, resistance handling, build-height bounds and entity exposure calculations with the Minecraft 1.20.1 implementation.
- Preserve vanilla 1.20.1 level-RNG ray-strength handling; use controlled matching seeds only in the isolated benchmark.
- Preserve vanilla 1.20.1 finalization RNG/order semantics: retain the full selected-position set including air, shuffle it with level RNG before mutation, keep server-emitted sound pitch off the gameplay RNG stream, and defer queued tasks’ ray-strength draws until they become active so later explosions cannot interleave RNG before the current explosion’s shuffle.
- Snapshot block positions before lifecycle callbacks so `onRemove`, physics, POI and explosion hooks cannot retain the scheduler's reusable mutable cursor.
- Correct chunk mutation bookkeeping and propagate lighting, block-entity and neighbor updates.
- Fix time-sliced post-update resumption and tighten deadline checks during ray calculation, mutation, lighting and neighbor propagation.
- Add deterministic vanilla ray-selection, resistant-center, empty-air and time-slicing regression tests.
- Add a Forge in-world GameTest plus repeatable Fabric/Forge dedicated-server + real-client explosion benchmarks with persisted evidence.

- Release live chunk references at every ray/mutation yield and reacquire the registered chunk before resuming.
- Dirty each successful removal even after an intervening save; restore vanilla per-write skylight, empty-section and light-check bookkeeping before yielding, with slice-batched client updates.
- Dispatch neighbor and shape updates with every committed removal, including notifications to not-yet-removed candidates inside the final crater. Normal shutdown no longer discards physics needed by surviving sand/support-dependent blocks.

## Build and release

- Add shared PR/release checks for JVM tests, both Minecraft 1.20.1 loader builds, artifact metadata and release automation regression tests.
- Publish a version-tagged GitHub release automatically when mod_version changes on main, with verified Fabric/Forge JARs, checksums and a source-commit manifest.
- Support optional CurseForge publication through repository configuration.

- Enforce monotonic stable-version tag history on manual, repair-push and final publication paths; reject shallow histories.

## Integration verification

- Gate PRs and releases on Forge GameTest plus real Fabric and Forge graphical-client runs.
- Require exact seeded vanilla/fast craters, authoritative client block/light receipts, a larger stress pair and save/reload equality.
- Freeze both launches before starting; reject source/artifact drift, retain every run and require clean process shutdown.
- Rename elapsed scheduler CPU claims to active-work duration and retain separate server-tick, client-acknowledgement and render-gap measurements.

- Require both loaders to demonstrate real ray/mutation chunk unload and replacement, preserved partial removals, and immediate partial-slice normal shutdown/reload with a vanilla block/light control.
- Wait boundedly for existing asynchronous light work in Forge GameTest instead of racing its unpaced tick timeout; retain exact initialization and removal-light assertions.
- Require the partial-save sand fixture to preserve scheduled falling ticks, verify the exact saved prefix before ticking, then match the vanilla landing position and block/light state after at least 40 ticks. Unfinished explosion work still does not resume after restart.

## Scope and limitations

No general vanilla explosion loot/custom callback parity or universal performance multiplier is claimed. The no-drops scenario is the equivalent-loot comparison. Client acknowledgement includes test coordination, and rendered-frame callbacks are not GPU fences. See TESTING.md for measured boundaries and fixture coverage. The tick budget is cooperative, not a hard cap.
